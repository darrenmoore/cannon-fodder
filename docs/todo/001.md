# 001 — make it look like the original

Worked through against `docs/original-images/`, using the loop in
[../loop.md](../loop.md). Screenshots of the result are in `game/shots/final/`.

## Done

- **a better hud** — the original's left sidebar, not a browser toolbar. The
  squad is listed by name, so a casualty reads as a name leaving a list.
- **standard ui components** — [`ui.ts`](../../game/src/ui.ts): panel, button,
  plate, readout, meter. The sidebar, the mission select and the end-of-mission
  panel are all built from them, so they cannot drift apart.
- **celebration and a clear button to next level or try again** — the end panel
  names the casualties, says how many came home, and offers *Next mission* /
  *Replay* / *Mission list*. A loss no longer restarts itself out from under you.
  `npm run playtest` asserts all of it.
- **the outside of the map is no longer predictable** — `border()` drew a
  rectangle of uniform thickness; `frame()` walks the thickness per edge and
  throws copses inland and clearings back into it.
- **front page** — no left border bars, missions grouped into theatres (The
  Jungle / The Desert / The Ice), laid out as a grid. `Theatre.locked` exists and
  is unwired, so making later theatres earned is a data change.
- **sand** — the desert missions had almost none. `dunes()` lays broad merging
  drifts, `verge()` wears the ground either side of a road down to it, and the
  renderer combs it with wind ripples.
- **the ice one: the middle of the water looked like land** — it was being
  painted in the snow palette. Arctic water is now the most saturated thing on
  the map, deliberately: it is the one colour that says "this is a hole, not a
  floor".
- **make it a bit darker** — the arctic had no black in it at all. The original's
  frame is 14% pure `#000000`; ours bottomed out at `#04070a`. Crag and pine now
  reach true black, which is what the snow is bright *against*.
- **improve the map tiling** — the whole of `terrain.ts`, `ground.ts`,
  `canopy.ts` and `palette.ts`. See below.

## The tiling, since it was the big one

> "i think you'll need to build a much better tiling method or maybe this one
> will do but we need perhaps more meta data, one block with 1 ascii might not
> be enough"

Right about the metadata, and the fix keeps the one-character map. All the extra
metadata is **derived** at load time rather than authored:
[`terrain.ts`](../../game/src/terrain.ts) computes, per tile, its material
class, how deep inside its own mass it sits, which contiguous mass that is,
8-neighbour match masks, and **signed distance fields** for water, foliage,
trees, tall grass and rock.

The distance fields are what changed the look. Sampled bilinearly with the
sample point displaced by noise first, a staircase of square tiles becomes a
curve that owes nothing to the grid. Every shoreline, treeline and crag edge is
now one threshold on one of those fields.

Then: nothing that forms a mass is drawn per tile any more. Trees, tall grass and
rock outcrops are each baked as one continuous layer — one sprite per tile on a
16px grid is a repeating motif you can read across a whole mission.

Full detail in [design.md](../design.md#terrain-as-shape).

## Also done — the men

They looked, in the owner's words, too perfect: stacked symmetrical rectangles,
evenly shaded, six identical figures on a 3x2 lattice all facing the same way.
Fixed at three levels — the sprite (a lit helmet over a near-black body scattered
with kit, nothing symmetrical), the roster (four baked variants per unit type,
chosen by actor id so a man keeps his kit), and the spawn (`squad()` scatters
them, and each starts on a slightly different facing). Corpses sprawl now, with
the helmet knocked clear. See [design.md](../design.md#the-men).

## Not done

- **more types of trees.** The canopy varies in tone and lump size across a map,
  but a palm and a broadleaf are the same mass in different colours. Distinct
  species — and individual palms standing in open ground, which the reference
  has — would want a scattered-prop pass on top of the mass.
- **Trees no longer sway.** Per-instance wind was a property of there being one
  sprite per tree. The trade was worth it, but the map is stiller than it was;
  getting it back means baking a few wind phases, or keeping the outermost fringe
  of the mass as sprites.
